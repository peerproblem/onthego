Handoffs, not homework

Pick up exactly where you left off.

Switching machines usually means a throwaway commit, a push, a pull, and explaining everything to your agent again. onthego carries the whole working state instead: staged, unstaged, and untracked work, plus the sessions you were having with Codex and Claude Code.

It knows which way to go.

sync compares both sides with their last handoff and moves work only away from the side that did not change. When both changed, it stops and asks you. Nothing is merged behind your back.

Setup in a minute

Connect the devices you already own.

If one device can ssh into the other, you are ready. Run commands from the device that can reach the other one.

  1. Turn on SSH on the laptopmacOS: System Settings > General > Sharing > Remote Login
  2. Copy your key onceSo handoffs never wait for a password.
  3. Pair, install, and go--install copies the same onthego version over SSH.
# inside your project on the desktop onthego init ssh-copy-id me@laptop.local onthego device add laptop --host me@laptop.local --install onthego sync laptop
  1. Sign in to Tailscale on both devicesAny network works: home, office, café, phone hotspot.
  2. See your tailnetonthego tailscale lists devices and what each one still needs.
  3. Pair by nameThe MagicDNS name keeps working when IP addresses change.
onthego tailscale # Devices on your tailnet: # laptop macOS online laptop.tail1234.ts.net onthego device add laptop --tailscale me@laptop --install onthego sync laptop
  1. No Node.js needed on the serverThe npm package carries every platform; --install sends the right one.
  2. Drive everything from your laptopThe server never has to reach you. sync works in both directions.
  3. Upgrade with one commanddevice install brings the server to your version.
onthego device add vps --host me@vps.example.com --install onthego sync vps # send the work up # ...work on the server... onthego sync vps # bring it back onthego device install vps # after upgrading locally
What moves

The work travels. The machine stays itself.

Travels with you

  • Staged and unstaged changesKept separate, with binary files and executable bits.
  • Untracked files and missing Git historyOnly the objects the other side does not have.
  • Codex and Claude Code sessionsRecent sessions for this project, paths remapped, content untouched.
  • Secrets, only when you ask--include-secret .env travels encrypted, outside Git objects.

Stays on each device

  • node_modules, caches, build outputYour local environment is never overwritten.
  • Git config, hooks, remotes, stashesThe destination repository keeps its own settings.
  • Agent logins and global databasesSign in to each agent on each device, as usual.
  • .env and other credential filesDetected and reported, never sent by default.

No account. No server. No AI.

  • Direct.Your devices talk over your own SSH. There is no relay, no cloud copy, no sign-up.
  • Encrypted and pinned.Every package is encrypted for the receiving device and signed by the sender. A device that changes keys is rejected.
  • Never silently merged.When both sides changed, onthego stops. Anything replaced is kept as a Git backup that onthego undo restores.
  • Small and open.One MIT-licensed binary for macOS and Linux. It moves your files; it does not think for you.
