One command

It reads like a sentence, and decides with care.

You never pick a direction. sync looks at what changed on each side since your last handoff and only moves work away from the side that did not change. If both changed, it stops and asks. Nothing is ever merged behind your back.

onthegothe tool syncdecide, then move laptopa paired device
push

Only this side changed

Your new work goes to the other device, together with the sessions you were having.

pull

Only the other side changed

It brings the work home. The same happens when you handed work off and simply want it back.

stop

Both sides changed

It stops and tells you the two ways out: push --replace or pull --replace. A Git backup is kept either way.

What it packs

The work comes along. Each machine stays itself.

Everything travels as one package, encrypted for the receiving device and signed by the sender. The destination is updated in place, so your editor, shells, and dependency folders keep pointing at the same directory.

In the bag01

  • Staged and unstaged changesKept apart, with binary files and executable bits.
  • Untracked files and missing historyOnly the Git objects the other side does not have yet.
  • Codex and Claude Code sessionsThis project's recent sessions, paths remapped, words untouched.
  • A secret, when you name it--include-secret .env travels encrypted, outside Git objects.

Stays home02

  • node_modules, caches, build outputYour local environment is never overwritten.
  • Git config, hooks, remotes, stashesThe receiving repository keeps its own settings.
  • Agent logins and global databasesEach agent signs in on each device, as usual.
  • .env and other credential filesFound, reported, and left alone by default.
Three routes

Use the machines you already have.

If one device can ssh into the other, you are ready. Run commands from the side that can reach the other one; a laptop can send work to a VPS and bring it back without the VPS ever reaching the laptop.

Same network

Turn on Remote Login (macOS) or sshd (Linux), copy your key once, and pair.

ssh-copy-id me@laptop.local
onthego device add laptop \
  --host me@laptop.local --install
onthego sync laptop

Across networks

With Tailscale, pair by device name. onthego tailscale shows your tailnet and what is missing.

onthego tailscale
onthego device add laptop \
  --tailscale me@laptop --install
onthego sync laptop

To a VPS

No Node.js on the server. --install sends the right binary, and device install upgrades it later.

onthego device add vps \
  --host me@vps.example.com --install
onthego sync vps   # up
onthego sync vps   # and back
FAQ

Fair questions.

Is this a sync daemon running in the background?

No. Handoffs are explicit: you run sync when you switch machines, so you always know which device has the work. Nothing watches your files.

Do I need an account, a server, or an API key?

No. Your devices talk directly over the SSH you already use. There is no relay, no cloud copy, and no AI feature. onthego only moves files.

What happens if I edit on both machines?

sync stops and explains your options. Whichever side you replace is saved first as a Git backup, and onthego undo puts it back.

Will my .env or tokens end up on the other device?

Not by default. Credential files are detected and left behind. If you really want one on the other side, --include-secret carries it encrypted, never inside Git objects.

Which agents and platforms are supported?

Codex CLI and Claude Code, on macOS and Linux (arm64 and amd64). Sessions are resumed by ID with the agent's own resume command; each device signs in to the agent separately.
